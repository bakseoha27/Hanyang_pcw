# 신규입사자 서류 제출 (onboarding)

한양이엔지(주) PCW 현장 신규입사자용 **모바일 제출 페이지**와 **관리자 페이지**입니다.

- 제출: `https://bakseoha27.github.io/Hanyang_pcw/onboarding/`
- 관리자: `https://bakseoha27.github.io/Hanyang_pcw/onboarding/admin.html`

## 어떤 정보를 다루나

주민등록번호 전체, 신분증·통장사본, 건강검진 결과(민감정보)를 받습니다. 그래서 이 앱은
`한양 pcw팀` 앱의 다른 테이블과 **보안 구조가 다릅니다.**

| 구분 | 권한 |
|---|---|
| `anon` (브라우저 공개 키) | `onboarding_submissions` **INSERT 만** · Storage `onboarding-docs` **업로드만** |
| `onboarding_otps` (인증번호) | `anon` 접근 불가 (정책 없음 + 권한 회수, Edge Function 만) |
| 조회 / 내려받기 / 삭제 | `anon` 불가 (정책·권한 없음) |
| 관리자 | Edge Function `onboarding-admin` (서비스롤 키는 함수 안에서만) |

관리자 인증은 **지정 관리자(이름 + 전화번호, `onboarding_admins`)** + **관리자 암호**
(`app_secrets.admin_passcode`, SHA-256 대조) 두 가지를 모두 만족해야 합니다.
전화번호는 **하이픈 유무와 관계없이 숫자만 비교**합니다(`010-9886-2959` = `01098862959`).
지정 관리자 7명(2026-11-27 확정): 박서하 · 김근하 · 이애영 · 이진수 · 김창겸 · 임재운 · 이빈.
지정 관리자를 추가하려면 DB에서:

```sql
insert into public.onboarding_admins (name, phone) values ('이름', '010-0000-0000');
```

## 휴대폰 문자 본인인증 (2026-11-27 v6)

사이트에 들어오면 **맨 처음 본인인증 화면**이 뜹니다. 인증을 마쳐야 서류 작성 폼이 열립니다.

```
이름        [            ]
전화번호    [ 010-0000-0000 ]
            [ 인증번호 받기 ]
  → 문자 발송 후
  인증번호 6자리 [ 123456 ]   ⏱ 5:00        [다시 받기]
            [ 인증 확인 ]

            🔐 관리자로 로그인하기
```

- **인증번호 받기**: 솔라피 문자 `[한양 pcw팀] 본인확인 인증번호는 [123456]입니다. (5분 이내 입력)`
  - 같은 번호 **60초 쿨다운**, 번호당 **1시간 5건**, 전체 **1시간 40건** 제한 (솔라피 하루 50건 보호)
  - 발송은 고정 IP 서버의 프록시(`SOLAPI_PROXY_URL`)만 거칩니다. API Secret 은 브라우저·Edge Function 어디에도 없습니다.
- **인증 확인**: 6자리가 맞으면 일회용 `otp_token`(2시간)을 발급합니다. 5번 틀리면 다시 받아야 합니다.
- **인증 통과 후**: 기존 서류 폼이 열리고 **성명·휴대폰 번호가 인증된 값으로 채워져 잠깁니다**(`readOnly`).
  제출할 때 `otp_token` 을 함께 보내고, DB 트리거가 **토큰 유효성 + 이름·전화번호 일치**를 확인한 뒤 토큰을 소모합니다.
  (그래서 가짜 이름·남의 번호로는 제출 자체가 거부됩니다.)
- **새로고침**: 같은 탭에서는 `sessionStorage` 의 토큰으로 폼이 유지됩니다(문자를 다시 받지 않음). 탭을 닫으면 다시 인증합니다.
- **🔐 관리자로 로그인하기**: 문자 인증 없이 이름·전화번호·관리자 암호를 확인하고 `admin.html` 로 바로 이동합니다.
  (통과하면 `admin.html` 이 자동 로그인 상태로 열립니다.)

| 구성 | 설명 |
|---|---|
| `public.onboarding_otps` | `phone`·`name`·`code_hash`(sha256)·`expires_at`(5분)·`attempts`·`verified_token`·`token_expires_at`(2시간)·`used_at` |
| `public.onboarding_require_otp()` | 제출 INSERT 전 검증 트리거 (서비스롤 등록은 통과) |
| `onboarding_submissions` | `otp_token`(저장 안 함) · `otp_verified_at`(인증 시각) |
| Edge Function `onboarding-otp` | `action: send` / `verify` / `guest` (`verify_jwt: false`, `SOLAPI_PROXY_URL`·`SOLAPI_PROXY_TOKEN` Secret 사용) |
| `js/otp.v10.js` | 첫 화면 게이트 · 타이머 · 재발송 쿨다운 · 관리자 바로 로그인 · 게스트 모드 |

## 게스트 모드 — 신규자 페이지 미리보기 (2026-11-27 v10)

- 신규자 페이지(`index.html`) 첫 화면 맨 아래 **`🔐 관리자로 로그인하기` 바로 아래**에
  아주 작은 연한 회색 글씨(`font-size:11px; color:#9CA3AF`)로 **`게스트 모드`** 가 있습니다.
- 누르면 암호 입력창이 뜨고, 암호 **`seoha`** 를 넣으면 **문자(OTP) 인증 없이** 서류 작성 화면 전체
  (사진 편집기 · 검진 PDF 자동 판독 · D2 토글 등)를 둘러볼 수 있습니다.
  암호는 Edge Function `onboarding-otp` 의 `action: 'guest'` 가 확인합니다(Secret `GUEST_PASSCODE`, 없으면 `seoha`).
- 게스트 모드에서는 상단에 **`👀 게스트 미리보기 모드`** 배지가 붙고,
  **`서류 제출하기` 를 눌러도 DB 저장·파일 업로드 없이** `게스트 미리보기 모드에서는 실제 제출되지 않습니다` 안내만 뜹니다.
  (설령 우회해도 DB 트리거가 OTP 토큰을 요구하므로 실제 제출은 거부됩니다.)

### 자동 판독 규칙 (2026-11-27 추가)

- **D2 판정**: `소견서`·`약봉투` 칸은 **평소 숨김**이고, 검진 영역 아래 **`D2 판정이신가요?`** 체크로 엽니다.
  검진 PDF 글자에 `D2`(예: `판정 D2`, `건강구분 : D2`, `D2 유소견`)가 있으면 **체크가 자동으로 켜지며** 칸이 펼쳐지고,
  빨간 안내창으로 **소견서(필수)·약봉투(선택)** 를 안내합니다. 체크를 끄면 다시 접히지만,
  PDF에서 D2가 감지된 경우엔 **소견서 필수는 그대로 유지**됩니다(안내창의 버튼으로 칸을 다시 열 수 있음).
  D2인데 소견서가 없으면 제출을 막습니다. D2 여부는 `files_json` 의 해당 파일 `d2: true` 로 저장됩니다.
- **검진일 1년 유효**: 검진일이 **오늘 기준 1년 전 같은 날짜**보다 이전이면
  `❌ 검진일로부터 1년이 지난 서류는 사용할 수 없습니다...` 를 띄우고 제출을 막습니다(수동 입력 날짜도 동일).

### 사진 자동 정리 · 편집 (2026-11-27 추가, v4)

`📷 사진 올리기` 의 **신분증 · 기초이수증 · 통장사본**에 사진을 고르면 편집 창이 바로 열립니다.
(증명사진은 기존처럼 JPG 변환만, PDF 는 편집 없이 그대로 올라갑니다.)

- **여백 자동 자르기**: 위·아래·좌·우에서 캡처 여백(흰색·검정·회색 단색)인 줄을 찾아 잘라 냅니다.
  실제 사진 배경처럼 노이즈·그라데이션이 있는 곳은 자르지 않도록 한 줄 안의 밝기 폭(14)과
  가장자리 기준색과의 차(10)를 엄격하게 보고, 한 변에서 **45%까지만** 자르며 결과가 **25% 미만**이면 취소합니다.
- **흐릿함 경고**: 잘라 낸 결과의 회색조 640px 축소본에서 **라플라시안 분산**을 계산해
  `12` 미만이면 `⚠️ 사진이 흐릿해서 글자가 잘 안 보일 수 있어요!` 배너를 띄웁니다.
  배너에서 **[다른 사진 다시 고르기]** 또는 **[그대로 사용]** 을 고를 수 있고, 그대로 쓰면 첨부 카드에
  `⚠️ 흐릿함 의심` 표시가 남습니다.
- **편집 창**: `↻ 90° 회전` · `자동 여백 자르기`(지금 네모 안쪽에서 다시 찾기) · `초기화`(처음 사진)
  · 네모(8개 손잡이)를 터치·드래그해 직접 자르기 · `이대로 적용`.
- 적용하면 Canvas 로 **JPEG(품질 0.9, 최대 2200px)** 로 저장하고, 파일명 규칙(`신분증(성명)` 등)은 그대로입니다.

Storage 객체 키는 ASCII만 허용되므로 실제 경로는 `{제출id}/{서류종류}.{확장자}`이고,
위의 한글 이름은 DB(`files_json`)에 저장해 **다운로드할 때 그 이름으로** 내려받습니다.

## 관리자 — 상단 탭 6개 (2026-11-27 v10)

탭마다 아래에 작은 부제가 붙습니다. **한 사람은 반드시 한 탭에만** 들어갑니다(카운트 배지 = 그 탭의 실제 인원 수).

| 탭 | 부제 | 들어가는 사람 |
|---|---|---|
| **진행중** | 서류수집중 | `입사예정`(`submitted`) · 취합 전(`archived_at` 없음) · 퇴사 아님 |
| **취합완료** | 서류접수완료 | `입사예정` · 취합완료(`archived_at` 있음) · 퇴사 아님 |
| **보류** | 서류보류 | `입사보류`(`hold`) · 퇴사 아님 |
| **확정** | 근무중인원 | `근무중`(`hired`) · 퇴사 아님 — 홍채까지 마치고 실제 근무중인 인원 |
| **전체** | 전체인원 | 모든 인원 + 다중 필터 |
| **퇴사** | 퇴사자 | `status='resigned'` 또는 퇴사일/퇴사처리일이 있음 |

- **퇴사 탭에서만 목록 표에 `특이사항` 열이 보입니다**(다른 탭에서는 숨김). 특이사항은 `박서하: 내용` 으로 보입니다.
- **[전체]** 탭 위에 **다중(중복) 필터 3종** — 같은 줄 안의 체크는 OR, 줄끼리는 AND.
  - **상태**: `입사예정` · `근무중` · `입사보류` · `퇴사`
  - **성별**: `남자` · `여자`
  - **외주/업체**: 기본 `외주` · `태림` · `건우` · `미래` + **[+ 업체 추가]**(`onboarding_vendors` 에 저장)
- 인원을 체크하면 **[선택한 인원 처리 ▾]** 드롭다운이 열립니다(0명이면 비활성):
  - **✅ 확정(근무중)** (`set_status hired`) · **📁 취합완료** (`set_status submitted` + `archive`) ·
    **⏸️ 입사보류** (`set_status hold`) · **▶️ 진행중 복귀** (`submitted` + `unarchive` + 퇴사일 비움) ·
    **🚪 퇴사 처리** (`set_status resigned`, 퇴사일이 비면 오늘) · **🗑️ 입사취소 삭제**(확인 후 서류까지 삭제)
  - 고르면 확인 후 바로 실행되고 선택이 풀리며 목록이 갱신됩니다(`selectedIndex = 0`).
- 이동·복구는 Edge Function `onboarding-admin` 의 `archive` / `unarchive` / `set_status` / `update_meta` 가 처리합니다.

## 관리자 — 날짜 정렬 · 날짜만 검색 (2026-11-27 v10)

- 표 머리글 **`한양교육일자` · `홍채등록일자` · `퇴사일자`** 를 누를 때마다 **기본 → 최신순 `↓` → 오래된순 `↑`** 로 바뀝니다
  (날짜가 없는 사람은 항상 뒤로). 같은 정렬을 목록 위 **[정렬 ▾] 드롭다운**에서도 고를 수 있습니다(모바일 포함).
- 검색줄 옆 **`날짜 검색: [한양교육일 / 홍채등록일 / 퇴사일 ▾] [YYYY-MM-DD] [✕]`** 로
  그 날짜와 **정확히 일치하는 인원만** 볼 수 있습니다. **✕** 로 초기화합니다.

## 직종 자동 분류 (2026-11-27 v7)

제출 폼에서 **`☑ 용접공입니다`** 를 체크하면 직종은 무조건 `용접공` 입니다.

단가는 `15` 처럼 만 단위로 적어도 되고 `150000` 처럼 원 단위로 적어도 됩니다(그 외 글자·`미기재` 는 분류하지 않음).

| 단가 | 직종 |
|---|---|
| `24` · `240000` (24만원) | **용접공** |
| `14` ~ `19만` (`140000 ≤ 단가 < 200000`) | **보통인부** |
| `20만` 이상 (`200000 ≤`, 24만 제외) | **배관공** |
| 그 외 (13만 이하 · 미기재 등) | 빈칸 — 관리자가 직접 고름 |

- 자동 분류된 직종은 **경력증명서 파일 이름**(`성명 경력증명서(직종).pdf`)과 **엑셀 `직종` 열**에 그대로 쓰입니다.
- 단가와 실제 직종이 다른 경우(예: 14만원인데 배관공)는 **관리자 상세 시트의 `직종` 선택**에서 고치면 됩니다.

## 관리자 — ⏸️ 입사보류 (2026-11-27 v8)

입사가 미뤄지는 사람을 **`입사보류`** 로 따로 표시합니다.

- **상세 시트 상태 선택**: 인원 상세 위 **`상태`** 줄에 `입사예정` · `입사확정(근무중)` · `⏸️ 입사보류` · `퇴사` 네 버튼이 있고,
  **한 번 누르면 바로 저장**됩니다(현재 상태는 파란 테두리로 표시).
  - `⏸️ 입사보류` 를 한 번 더 누르면 **해제**되어 `입사예정` 으로 돌아갑니다.
  - `퇴사` 는 확인 후 **퇴사일자를 오늘로** 저장합니다. `입사예정`·`입사확정`·`입사보류` 로 바꿀 때 퇴사일자가 남아 있으면 함께 지웁니다.
- **[전체] 탭 상태 필터 4종**: `입사예정` / `근무중` / `입사보류` / `퇴사` — 중복 체크(OR) 가능.
- **목록 배지**: `hold` 인원은 노란 **`입사보류`** 배지로 표시됩니다(퇴사는 회색).
- **엑셀 `상태` 열**: `입사보류` 로 나갑니다.
- **[➕ 신규자 직접 추가]** 에도 **`상태`** 선택(`입사예정` / `⏸️ 입사보류`)이 있습니다.
- DB: `status` CHECK 에 `'hold'` 추가(`'submitted'`,`'hired'`,`'hold'`,`'resigned'`,`'cancelled'`).
  Edge Function 은 `set_status` · `update_meta`(`status`) · `create_manual` 에서 `hold` 를 받습니다.

## 엑셀 취합

관리자 페이지의 **[📊 엑셀 취합 다운로드]** 는 서하 님의 실제 양식(`확정 (2)` 시트)의
열 순서·너비·머리글 색을 그대로 따릅니다.

`No. · 성명 · 외주 · 업체구분 · 주민번호 · 성별 · 입사일자 · 퇴사일자 · 주소 · 핸드폰기종 · 휴대폰 · 월급/일당 · 은행명 ·
계좌번호 · 입금자명 · 직종 · 숙소 · 총경력 · 반도체경력 · 이메일 · 혈액형 · 조끼 사이즈 ·
안전화 사이즈 · 보안경(일반/안경) · 보유 자격 현황 · 소개자`

그 뒤에 **서류 제출 현황**(신분증·기초이수증·통장사본·증명사진·건강검진·소견서·경력증명서 O/X,
검진일/종류, 제출일, 상태, 동의 일시 3종)을 덧붙이고, 맨 끝에 **`특이사항`** 열(`박서하: 내용` 줄바꿈 누적)을 둡니다.
`업체구분` 은 `outsource_company`(없으면 외주 체크 시 `외주`), `상태` 는 `취합완료`/`입사보류`/`퇴사`/`입사확정`/`제출` 입니다.
`입사일자`는 관리자가 넣은 `hire_date` 값을, `퇴사일자`는 `resign_date`, `외주`는 `is_outsource`(O/빈칸), `성별`은 `gender` 를 씁니다.
`숙소` 열은 양식 순서를 지키려고 남겨 두고 **항상 빈칸**입니다(숙소 입력란은 2026-11-27 제거).
`직종` 열은 **저장된 `job_role`** 값입니다 — 용접공 체크 시 `용접공`, 아니면 단가로 자동 분류(`보통인부`·`배관공`·`용접공`),
관리자가 상세에서 고쳤으면 그 값(예: `품질관리자`, `공사관리자`)이 그대로 나갑니다.
`입금자명` 열은 `입금자명(예금주)` 입력값이며, **`본인 명의` 가 체크되어 있으면 `성명` 과 같습니다**(DB `account_holder`). 건강검진을 여러 개 올리면 `검진일 / 종류` 칸에
`2026-10-16 배치전 / 2026-10-16 일반` 처럼 모두 적힙니다.

## 제출 항목 (2026-11-27 기준)

- 필수: 성명 · 주민번호 · 주소 · 휴대폰 기종/번호 · 본인 명의 · 은행/계좌 · **입금자명(예금주)** · 단가 · 총 경력 · **반도체 경력** ·
  **이메일** · 혈액형 · 조끼/안전화 · 보안경 · 신분증 · 기초이수증 · 통장사본 · 증명사진 · 경력증명서 · 동의 3종
- **건강검진은 선택**(2026-11-27부터). 올리지 않아도 제출되며, 올린 파일은 검진일·종류와 1년 유효기간을 그대로 검사합니다.
- 선택: 용접공 여부 · 보유 자격 · **건강검진** · 소견서 · 약봉투 · **소개자/추천인**
- 단가 칸은 자유 입력(`미기재` 도 허용). 서류는 **📷 사진 올리기**(신분증·기초이수증·통장사본·증명사진)와
  **📄 서류 올리기**(건강검진·경력증명서·D2) 두 구역으로 나뉘고, 카드에는 변환 파일명이 아니라 **짧은 이름과 원본 파일명**만 보입니다
  (변환된 저장 이름은 DB `files_json`·관리자 상세·ZIP 에만 쓰입니다).
- 소견서·약봉투 칸은 `D2 판정이신가요?` 체크(또는 검진 PDF의 D2 자동 감지)일 때만 나타나고, 그때 소견서는 필수입니다.
- `입금자명(예금주)` 는 `본인 명의 계좌 확인(필수)` 체크 시 `성명` 과 실시간 동기화되고, 체크를 풀면 직접 입력할 수 있습니다.
- **본인 명의 계좌만 입사 가능**: `본인 명의 계좌 확인` 이 체크되어 있지 않으면서 `입금자명 ≠ 성명` 이면
  `본인 명의 계좌만 입사할 수 있습니다...` 로 제출을 막습니다(가족·타인 명의 계좌 차단).
- 없어진 항목: `숙소 사용`(폼·DB 저장값), `직종` 선택(→ `용접공` 체크 + **단가로 자동 분류**, 관리자가 상세에서 수정)
- DB `housing` 컬럼은 그대로 두고 `null` 저장, `job_role` 은 `'용접공'` 또는 `''`
